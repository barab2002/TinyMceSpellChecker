Quick Start

Option A — Docker Compose (recommended)

1
Clone and configure
git clone https://github.com/barab2002/TinyMceSpellChecker.git
cd TinyMceSpellChecker
cp .env.example .env        # edit as needed
2
Start everything
docker compose up -d --build

# API:         http://localhost:8000
# Docs:        http://localhost:8000/
# Dictionary:  http://localhost:8000/dictionary
# Approvals:   http://localhost:8000/approvals
# Swagger:     http://localhost:8000/docs
3
Verify
curl http://localhost:8000/health

Option B — Local Python

cd backend
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
uvicorn app.main:app --reload --host 0.0.0.0 --port 8000

Plugin Integration

Copy plugin/hebrewspellcheck/plugin.js into your app's static assets, then configure TinyMCE.

Minimal (3 required options)

tinymce.init({
  selector: '#my-editor',
  external_plugins: {
    hebrewspellcheck: '/static/plugins/hebrewspellcheck/plugin.js',
  },
  toolbar: 'hebrewspellcheck hebrewspellcheck_clear | bold italic',
  hebrewspellcheck_api_url: 'http://localhost:8000',     // ← your API
  extended_valid_elements: 'span[class|data-word|data-suggestions]',
  browser_spellcheck: false,
});

All Plugin Options

Language Configuration

By default, all dictionaries found in backend/dictionaries/ are loaded. Set SPELLCHECK_LANGUAGES to restrict which languages are active.

# .env — load only Hebrew and English
SPELLCHECK_LANGUAGES=he-IL,en-US

# load all available dictionaries (default — leave empty)
SPELLCHECK_LANGUAGES=

To add a new language, drop its .aff and .dic files into backend/dictionaries/ and restart. The service auto-discovers them.

CodeLanguageFile pair

MongoDB Setup

When SPELLCHECK_MONGO_URI is set, the organisational dictionary switches from a local JSON file to MongoDB. This enables the word approval workflow.

Step 1 — Add to .env

# Local MongoDB
SPELLCHECK_MONGO_URI=mongodb://localhost:27017

# MongoDB Atlas (cloud)
SPELLCHECK_MONGO_URI=mongodb+srv://user:pass@cluster.mongodb.net

# Database name (default: spellcheck)
SPELLCHECK_MONGO_DB=spellcheck

Step 2 — Start with MongoDB in Docker Compose

# docker-compose.yml already includes a MongoDB service.
# Just make sure SPELLCHECK_MONGO_URI is set in .env:
docker compose up -d --build

Collections created automatically

CollectionPurpose
approved_wordsWords accepted during spell-check. Indexed on word (unique) and language.
pending_wordsWords suggested by plugin users. Status: pending → approved / dismissed.

Migration from JSON

If org_dictionary.json already has words, they are automatically migrated to MongoDB on first startup (idempotent — running again is safe).

Fallback behaviour

If MongoDB is unavailable at startup, the service falls back to the JSON file and logs a warning. Spell-checking continues without interruption.

Word Approval Workflow

1
User clicks "הוסף למילון"

The TinyMCE plugin calls POST /dictionary/suggest. The word is stored in the pending_words MongoDB collection.

2
Admin opens /approvals

The approval GUI shows all pending words with language, submission date, and optional context.

3
Admin approves or dismisses

Approve: word moves to approved_words and is accepted immediately (in-memory cache updated, no restart needed).
Dismiss: word is marked dismissed and remains flagged as a misspelling.

Without MongoDB: clicking "הוסף למילון" adds the word directly to the JSON dictionary (no approval step — same as previous behaviour).

API Reference

Full interactive docs with runnable examples are at /docs (Swagger UI).

POST /spell/check Check text for spelling errors ▼ 
# Request
{
  "text": "שלומ לכולם",
  "language": "he-IL",
  "options": { "includeSuggestions": true, "maxSuggestions": 5 }
}

# Response
{
  "language": "he-IL",
  "misspellings": [
    { "word": "שלומ", "start": 0, "end": 4, "suggestions": ["שלום"], "source": "hunspell" }
  ],
  "total": 1
}
GET /dictionary List all approved words ▼ 
curl http://localhost:8000/dictionary -H "Accept: application/json"
# { "words": ["Salesforce", "ZoomInfo"], "count": 2 }
POST /dictionary/suggest Suggest a word for approval (plugin) ▼ 
curl -X POST http://localhost:8000/dictionary/suggest \
  -H "Content-Type: application/json" \
  -d '{"word": "MyProduct", "language": "he-IL"}'
# { "status": "queued", "word": "MyProduct", "id": "664abc..." }
POST /dictionary/add Add a word directly (admin) ▼ 
curl -X POST http://localhost:8000/dictionary/add \
  -H "Content-Type: application/json" \
  -d '{"word": "MyProduct", "language": "all"}'
GET /dictionary/pending List pending word suggestions ▼ 
curl "http://localhost:8000/dictionary/pending?status=pending"
# { "words": [...], "total": 5, "status_filter": "pending" }
POST /dictionary/pending/{id}/approve Approve a pending word ▼ 
curl -X POST http://localhost:8000/dictionary/pending/664abc.../approve
# { "status": "approved", "word": "MyProduct" }
GET /health Service health check ▼ 
curl http://localhost:8000/health
# { "status":"ok", "hunspell_available":true, "storage_backend":"mongodb",
#   "pending_approvals":3, "custom_dict_words":42 }
